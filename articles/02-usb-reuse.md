# U盘做完启动盘后，无法格式化、容量变小怎么办？

作者：Eating-King-Git。根据本人操作记录与官方文档整理，含 AI 辅助写作和核查。整理日期：2026-11-21。

系统装好以后，启动U盘通常还能恢复成普通存储盘。先判断电脑看到的是一个小分区，还是整块设备都变小了，再决定是否重建分区。直接反复点“格式化”，可能一直只在处理其中一个分区。

我做Ubuntu启动盘时用过64GB U盘，也提出过“之后怎么恢复、为什么无法格式化”的问题。不过，当时没有留下完整报错和恢复成功记录。因此，这篇是依据官方说明整理的补充操作指南，不把某一种修复写成自己的亲测结果。以下以Ubuntu的“磁盘”（Disks）为主，适合准备清空U盘、重新作为存储使用的人。

## 一、先别格式化：U盘里还要不要保留文件？

如果需要找回启动盘制作前的照片、文档，先停止写入。重建分区、格式化和继续拷贝文件，都不是找回旧数据的步骤。

如果你已备份需要的内容，只想把U盘恢复为一个普通盘，可以继续。最好从电脑硬盘上的Ubuntu启动；不要在正在运行的安装U盘上改它自己的分区。先拔掉其他移动硬盘，也能减少选错对象的机会。

这里“恢复”指恢复正常存储用途，不保证找回旧文件，也不等于把旧数据安全擦除。GNOME官方特别提醒，格式化后仍可能恢复部分旧数据；出售或交给别人又是另一类需求。[GNOME：格式化可移动磁盘](https://help.gnome.org/gnome-help/disk-format.html)

## 二、标着64GB，系统显示约59.6GiB，是不是坏了？

不一定。64GB按十进制是640亿字节，除以1024的三次方，约等于59.6GiB。这是单位换算。文件系统还会占用一点空间。

真正需要区分的是三个数字：

| 看到的数字 | 它代表什么 | 下一步 |
|---|---|---|
| 整块设备约64GB／59.6GiB | 控制器向电脑报告的总容量 | 看下方分区是否占满 |
| 一个分区只有几GB，其余未分配 | 当前分区布局没有覆盖整盘 | 清空用途时可重建布局 |
| 整块设备本身也异常变小或反复消失 | 不能仅用“小分区”解释 | 换接口、换电脑确认，先排硬件问题 |

“磁盘”和“分区”不是同一个对象：一块U盘可以包含多个分区，文件管理器可能只显示其中可识别的卷。GNOME的“磁盘”左侧选设备，右侧看其内部布局，这比只看文件管理器里的盘符更清楚。[GNOME：管理卷与分区](https://help.gnome.org/gnome-help/disk-partitions.html)

## 三、怎样确认选中的是U盘，而不是电脑硬盘？

打开应用菜单，搜索“磁盘”或“Disks”。先看型号、容量和连接方式；拔下U盘时消失、插回时出现的设备，是一个有用的交叉核对。仅凭“最后一个磁盘”或设备名里的某个字母判断不可靠。

愿意用终端，可以先运行这条只读命令：

```bash
lsblk -o NAME,MODEL,SIZE,TYPE,TRAN,RO,MOUNTPOINTS
```

`NAME`是设备名，`MODEL`是型号，`SIZE`是容量；`TYPE`区分整盘与分区，`TRAN`可能显示`usb`，`RO`表示是否只读，`MOUNTPOINTS`表示正在挂载到哪里。部分设备不会完整提供型号或连接信息，不能把一个空字段当作故障。`lsblk`的默认输出会随版本变化，因此这里明确指定列。[Ubuntu 22.04：lsblk手册](https://manpages.ubuntu.com/manpages/jammy/man8/lsblk.8.html)

这一步的验收是：能把左侧选中的设备，与自己手里的U盘型号和容量对应起来。如果仍分不清，就不要进入格式化确认页。

## 四、为什么只格式化一个分区，容量没有恢复？

“格式化分区”是在既有分区内部建立文件系统，一般不会把外面的未分配空间吞进来。启动盘留下多个分区时，重做某个小分区，仍可能得到一个小盘。

如果确定清空整只U盘，目标是先建立新的分区表，再建立占用所需空间的分区。GNOME“磁盘”把整盘格式化与分区格式化分开；整盘对话框提供MBR、GPT等布局选项，并会提示数据处理范围。[GNOME 42整盘格式化实现与提示](https://github.com/GNOME/gnome-disk-utility/blob/gnome-42/src/disks/gduformatdiskdialog.c)

## 五、在“磁盘”里具体怎样恢复普通存储？

以下步骤会清除所选U盘的现有分区和文件。每个确认窗口都重新看一遍设备型号和容量。

1. 选中已经核实的U盘。关闭正在访问它的文件窗口和程序；如果分区仍挂载，用分区区域的停止按钮卸载。
2. 打开整块设备的菜单，选择“格式化磁盘／Format Disk”。不要把分区下面的“格式化分区”当成同一个入口。Ubuntu桌面版本不同，菜单图标位置可能不同，以文字和目标设备为准。
3. 选择分区表。普通小容量U盘、需要兼顾较老设备时，可以按界面的兼容提示选MBR；明确面向现代系统时可选GPT。这里选择的是分区布局，不是FAT32或NTFS。
4. 确认后，在新出现的空闲空间上点“＋”创建分区。若只需要一个普通数据盘，让它使用所需的全部空闲空间，再选择文件系统、填写卷名。
5. 再次确认目标后完成。等待操作结束，挂载新分区，在文件管理器中打开它。

如果界面只提供“格式化分区”，先回到整块设备的菜单。不要因为找不到按钮，就去照抄网上带有固定磁盘号的擦盘命令。具体分区格式化与安全弹出流程可对照[GNOME官方操作说明](https://help.gnome.org/gnome-help/disk-format.html)。

## 六、FAT、NTFS、ext4该选哪一个？

先考虑U盘将插到哪些设备，以及会放多大的单个文件，再看“磁盘”提供的兼容性说明。需要Windows和Linux交换文件，应选择双方都能读写的格式；只用于Linux时，ext4才更值得考虑。不要因为Ubuntu自己的根分区用ext4，就给所有U盘也选ext4。

对相机、电视或旧设备，应查设备自己的支持列表。尤其需要存放大型镜像或视频时，先确认单文件限制；“U盘剩余空间很多”和“这个文件能写进去”是两个条件。格式选择应跟着使用场景走，而不是默认“最新的一定最好”。

## 七、如果仍提示忙、只读或I/O错误怎么办？

“设备忙”通常意味着仍有程序使用它。先退出U盘中的终端目录，关闭文件管理器和相关程序，再尝试正常卸载；确认电脑从内置硬盘启动。不要靠强制卸载正在使用的系统盘解决。

“只读”需要换一条思路。看看读卡器有没有物理写保护开关，重新插接，换一个USB接口，再用另一台电脑交叉检查。`RO=1`是一条线索，不能单凭它认定某个具体硬件已经损坏。反复加`sudo`不会改变物理写保护。

如果伴随反复掉盘、输入输出错误，或者不同电脑都无法写入，先停止连续格式化。记录完整错误和设备识别情况；还要保留数据时，应优先考虑数据保护。重建分区能处理布局问题，不能保证修好失效的闪存或控制器。

## 八、怎样才算完成，而不是“按钮点完了”？

先确认新分区的容量与预期相符。复制一个不重要的测试文件，打开检查内容，然后安全弹出U盘、重新插入，再读取同一个文件。若准备跨系统使用，还要在目标系统上验证一次。

这能确认基本挂载和读写流程，却不能证明整只U盘每个位置都可靠，也不能排除虚标容量。对有过异常的U盘，不要马上拿它保存唯一一份重要资料。

最后保留三项记录就够了：设备型号与总容量、采用的分区表和文件系统、重新插入后的读写结果。比只记一句“格式化成功”，更方便下次定位问题。

## Linux命令小板块

| 命令 | 用来做什么 | 注意 |
|---|---|---|
| `lsblk -o NAME,MODEL,SIZE,TYPE,TRAN,RO,MOUNTPOINTS` | 查看设备和分区关系 | 本文只读检查，不修改磁盘 |
| `pwd` | 看当前终端所在目录 | 卸载U盘前避免仍停在它的目录里 |
| `cd ~` | 回到自己的主目录 | 不会删除U盘中的内容 |

本文没有需要照抄的整盘擦除命令。完成目标靠的是认对设备、选对作用范围，以及实际读写验收。
