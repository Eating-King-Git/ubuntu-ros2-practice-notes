# 从收到机械臂状态到三维显示：A3、RViz 与运动预览

作者：Eating-King-Git。根据本人操作记录与官方文档整理，含 AI 辅助写作和核查。整理日期：2026-11-21。

适用背景：Ubuntu 22.04、ROS 2 Humble，以及已经完成电脑端与设备网络检查的 A3 开发环境。本文整理的是一次已有接入记录和可视化过程，不提供自动启动真机运动的命令。

## 1. 这一阶段到底做到了哪里？

已经确认的历史结果包括：ROS 控制节点收到机械臂状态，RViz 显示真实关节位置，另有半透明模型显示预览目标；MoveIt Servo 在隔离环境中跑通了关节和末端方向的虚拟预览。

需要分清一个边界：**MoveIt Servo 的输出没有接到真机，自动测试没有向真机发送位移。** 真机侧已有带限制的关节点动界面，用户曾切换到实机模式，但现有记录不能据此写成完成了全面运动验收，更不能写成自主抓取已经实现。

整个过程可以分成五层：

```text
设备反馈 → ROS 消息 → 模型与坐标变换 → RViz 显示
                                         └→ 独立的虚拟预览
```

每向前一步，都应说明数据从哪里来、实际改变了什么。

## 2. 想看状态，为什么不能随便启动厂商节点？

因为节点启动可能不只是订阅消息。这次使用的控制节点按厂商流程会执行 `set_ready()`，进而使能机械臂。历史上是在用户明确要求后才启动，启动后有使能和位置模式状态反馈。

所以，“运行节点看看有没有数据”与“读取一个已有节点的状态”不是同一件事。前者要先检查构造流程和启动逻辑，后者也应使用明确只读的查看命令。SDK 示例常常把连接、准备和运动连着演示，复制时需要先看完整上下文。[厂商 SDK 与 ROS 示例](https://github.com/cvte-robotics/carm_demo)

本文只解释已有结果和查看方法；不把启动控制节点、发布使能或运动指令塞进环境验证代码块。

## 3. 收到哪些消息，才算接入有了实质进展？

这次记录中有三类反馈，每类都收到至少三条消息：真实关节状态、法兰笛卡尔状态和机械臂状态。真实关节包含六个关节名。

收到消息后还要看内容：关节名与顺序是否对应模型，单位是弧度还是角度，时间戳是否更新，连接和使能状态是否符合预期。一次旧消息不能证明反馈一直新鲜，六个数字也不能省掉名称映射直接塞给六个关节。

在**已由负责人确认正在运行的节点环境**中，加载正确的 ROS 环境和域配置后，可查看：

```bash
ros2 topic list
ros2 topic info /a3/real_joint_state
ros2 topic echo /a3/real_joint_state --once
```

这些是本项目的话题名，其他驱动应以自己的接口为准。`echo --once` 用于检查一条消息；若检查更新频率，需要另外观察一段时间。不要为了让列表出现内容而重复启动控制后端。

## 4. 六个关节角，怎样变成 RViz 中的机械臂？

需要模型和状态一起工作。URDF 描述连杆、关节和它们之间的关系；`JointState` 提供当前关节值；`robot_state_publisher` 据此生成坐标变换，RViz 才知道各个部件放在哪里。

```text
URDF：连杆与关节结构 ─┐
                     ├→ robot_state_publisher → TF → RViz
JointState：当前角度 ─┘
```

固定连接的变换与随关节变化的变换也有不同发布方式。初学时先检查模型是否完整、名字是否一致、固定坐标系是否存在，再处理显示样式。[robot_state_publisher 官方说明](https://github.com/ros/robot_state_publisher/blob/humble/README.md)

这次界面里，实色模型跟随真实反馈，半透明青色模型表示预览目标。颜色区分有实际用途：鼠标或键盘改变了预览模型，不应让使用者误以为真机已经到达那个位置。

## 5. 模型从哪里来？怎样知道方向没有画反？

模型来源是厂商 `carm-mujoco` 仓库，历史记录固定在提交 `0ea54f12ffe17b2f8f65eebbb51e6eab2b6af643`。当时只取得所需的 A3 MJCF 与 STL，再将名义关节轴、范围和几何转换为 URDF，没有运行厂商仿真脚本。[厂商模型仓库](https://github.com/cvte-robotics/carm-mujoco)

“看起来像机械臂”还不够。检查时发现模型名义法兰与控制器 `tool=0` 的定义存在约 6 mm 的 Z 向偏移，因此用显式固定变换修正坐标关系，保留了原来的网格和关节参数。这样读者能追溯差异来自坐标约定，而不是默默移动模型凑效果。

随后把模型计算的正运动学与控制器只读的正运动学结果比较。正运动学就是：给定关节角，计算末端的位置和方向。这些请求要求控制器计算，不是让机械臂移动到那些姿态。

历史记录为 16 个姿态，其中 12 个是保留验证点；最大位置差约 `6.38 × 10⁻⁶ m`，最大方向差约 `1.34 × 10⁻⁵ rad`。这些结果支持当时模型与控制器软件的计算约定一致。

它们**不是实物标定精度**：没有据此测量真实末端位置，也没有覆盖全部型号、夹具、负载与固件。网页上显示得很准，和实际机械结构的测量误差，是不同问题。

## 6. MoveIt Servo 预览解决了什么问题？

它把连续的小幅关节或末端速度输入转换为模型关节更新，适合检查按键方向、坐标系和连续输入过程。官方 Servo 具有关节限制、奇异性和碰撞相关处理，但依赖正确的模型、反馈和配置；输出接到哪里也必须明确配置。[MoveIt Servo 官方教程](https://moveit.picknik.ai/humble/doc/examples/realtime_servo/realtime_servo_tutorial.html)

本次把它接到虚拟模型，并与真实控制环境隔离。预览从一个非奇异的示例姿态开始；这里“初始姿态改变”只改变虚拟模型，没有要求真机跟随。

记录中的隔离集成检查跑通了键盘输入到 Servo 再到预览模型：有约 0.355° 的关节变化和 1.267 mm 的 X 向变化。检查所在隔离域中，真实运动话题的发布者数量为 0。另有 11 项边界测试使用假发布者完成。这些都是历史记录中的测试范围，不是本篇重新操作了设备。

预览能动，证明这段软件链路在测试条件下工作；它没有证明真机末端连续遥操已接通。

## 7. 有碰撞检查，为什么仍不能称“自动避障”？

因为软件只能检查模型和场景里已有的东西。当前环境没有接入深度相机或现场障碍地图，未知的桌面物品、夹具和线缆不会因为 RViz 有画面就自动进入碰撞场景。

本次模型采用厂商名义外形，未完成全部真实外形和碰撞包络测量。所以预览中的自碰撞或奇异性处理，只能按其模型和配置解释，不能扩大成现场安全保证。

这也是为什么显示、预览和实际执行需要分开验收：前两项能帮助发现坐标、关节和输入逻辑问题；实机运行还需要结合具体装配、空间、工具和操作规程。

## 8. 预览界面和真机界面有哪些容易误解的地方？

默认预览不等于“界面上的每个按钮都不会影响真机”。这次界面的软件急停按钮具有独立的真机命令用途；解释界面时必须按具体按钮说明，不能笼统承诺整页只读。

真机关节点动只在明确切换模式并持续按住输入时发布目标，切换时从真实位置重新开始；释放输入或窗口失去焦点会停止继续发送。但这属于位置跟踪：末次已经发出的微小目标可能仍由控制器完成，不能把停止发送等同于物理急停。

另外，关闭查看面板不会自动给独立运行的控制后端卸使能。是否仍使能，需要查状态并按设备的正式流程处理。仅关闭窗口就认为设备已断开，是很容易出现的误判。

## 9. 这一篇应该怎样验收和归档？

把结果按层记下来，后续才不会把预览成果误写成实机控制成果：

| 层次 | 历史已确认 | 仍未由这些证据确认 |
|---|---|---|
| 状态接入 | 三类反馈、六轴关节消息 | 全部接口与全部固件兼容 |
| 模型显示 | 真实反馈与预览目标分开显示 | 实物测量与标定精度 |
| 运动学核对 | 固定模型与控制器的 16 姿态计算对照 | 全工作空间物理精度 |
| 虚拟预览 | 隔离的关节及末端方向输入链路 | Servo 实机末端遥操 |
| 真机交互 | 已有受限制的关节点动界面 | 完整运动验收、自主抓取、现场避障 |

后续继续开发，应从所需能力的缺口开始补证据，而不是把已有画面包装成更大的完成项。

## Linux 常用命令小板块

下列命令用于查看已存在的 ROS 图，不启动控制器、不发布运动目标。

| 命令 | 用途 |
|---|---|
| `printenv ROS_DOMAIN_ID` | 确认终端属于哪个通信域 |
| `ros2 node list` | 查看当前发现的节点 |
| `ros2 topic list` | 查看已发现的话题 |
| `ros2 topic info 话题名` | 查看类型、发布者和订阅者数量 |
| `ros2 topic echo 话题名 --once` | 读取一条反馈并退出 |
| `ros2 interface show sensor_msgs/msg/JointState` | 查看关节消息字段定义 |
