# Ubuntu安装与启动出问题：先判断卡在哪一步

作者：Eating-King-Git。根据本人操作记录与官方文档整理，含 AI 辅助写作和核查。整理日期：2026-11-21。

安装Ubuntu时，最容易让人紧张的是“出现红字”“没有进入预想的系统”“Windows突然要求恢复密钥”。这些现象发生在不同阶段，处理方式也不同。先写清楚电脑已经走到哪一步，比立刻搜索一个通用修复命令更有用。

我的实际经历包括：从HP启动菜单进入UEFI U盘、试用Ubuntu、看到EFI分区检查提示、确认只格式化新建Linux分区，以及后来遇到Windows BitLocker恢复界面。安装U盘完全无法识别、GRUB严重损坏，则不是这次已发生并修好的案例。下面把真实经过和可供参考的排查方法分开写。

## 一、先把问题放进哪一个阶段？

| 停在哪里 | 先确认什么 | 这时还不能下的结论 |
|---|---|---|
| 开机菜单没有U盘 | 接口、启动介质、UEFI入口 | 不能直接认定Ubuntu不兼容 |
| 能选U盘，进不了试用桌面 | 镜像、写盘方式、具体屏幕错误 | 不等于硬盘分区坏了 |
| 安装器提示分区问题 | 目标磁盘、分区类型、完整报错 | 红字不等于应格式化EFI |
| 安装结束，仍进入旧系统 | 启动来源和固件启动项 | 不等于Ubuntu没有装入硬盘 |
| Windows要求恢复密钥 | BitLocker恢复界面和密钥ID | 不等于Windows文件已被删除 |

记录时拍下或抄下完整错误，说明是否插着U盘、之前改了什么。公开求助时，遮住恢复密钥、序列号和账户信息。

## 二、开机没有自动进入U盘，要重做启动盘吗？

先检查固件的启动菜单。我的HP机器通过`Esc`进入启动菜单，再用`F9`选择带有UEFI标识的U盘；这是该机器的操作经历，其他品牌应以自己的手册为准。

如果菜单中能看到U盘，优先选与原系统一致的UEFI启动入口。进入Ubuntu菜单后先选择试用模式，确认能够到桌面。Ubuntu官方提供了启动盘制作步骤；如果介质始终不能正常启动，再回到镜像来源、完整性和写盘流程逐项核对。[Ubuntu：制作启动U盘](https://ubuntu.com/desktop/docs/en/latest/how-to/create-a-bootable-usb-stick/)

本次我在试用桌面确认过Wi-Fi、显示、触控板、亮度和声音基本可用，然后才继续安装。这是这台机器的基础硬件检查，不能推广成所有同型号机器、所有外接设备都通过了兼容性测试。

## 三、如何确认当前以UEFI启动？

在试用桌面打开终端，可以运行：

```bash
if [ -d /sys/firmware/efi ]; then
    echo "当前会话以 UEFI 启动"
else
    echo "当前会话未发现 UEFI 接口"
fi
```

这只是检查当前启动环境，不会修改固件设置。它也不告诉你Secure Boot是否启用，不能代替完整的启动配置检查。不要把“UEFI”“GPT”“Secure Boot”混成一个开关：它们分别涉及启动方式、磁盘分区布局和启动组件的验证。

Ubuntu本身支持UEFI Secure Boot，并通过受信任的启动组件继续验证后续加载过程。因此，“先把Secure Boot关掉”不应成为遇到任何问题的第一步。若是第三方驱动签名或MOK注册问题，应针对屏幕上的具体提示处理。[Ubuntu：UEFI Secure Boot机制](https://documentation.ubuntu.com/security/security-features/platform-protections/secure-boot/)

## 四、EFI分区出现红色警告，要不要直接修复？

我的安装过程中，已有EFI分区出现了检查提示。随后做过一次只读检查，涉及的内容是卷标`SYSTEM`与另一处空卷标不一致；记录明确表明文件系统保持不变。这不支持“整块EFI分区严重损坏”的结论，也不是一次已经执行修复的记录。

当时使用了`fsck.fat -n`。其中`-n`很关键，官方定义为检查错误但不向文件系统写入。默认模式和自动修复模式则有不同的写入行为，不能只看命令名字就认为全都只读。[Ubuntu 22.04：fsck.fat手册](https://manpages.ubuntu.com/manpages/jammy/man8/fsck.fat.8.html)

这里不提供可以直接运行的固定设备号。需要检查时，先通过下面的命令确认实际分区：

```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINTS
```

它帮助把磁盘、分区、文件系统和挂载位置对应起来。只有确认是目标FAT分区、理解其当前使用情况后，才讨论具体检查命令。其他电脑的`p1`、`p7`没有通用含义。出现警告时，保留原有EFI和Windows分区，先读清楚问题，比直接格式化更合理。

## 五、预留150GiB，安装器显示约161062MB，是不是分错了？

本次出现过这组数字。150乘以1024的三次方，再除以一百万，约等于161061MB；不同界面取整后出现约161062MB并不奇怪。

判断是否选错空间，不能只比较数字大小，还要同时核对单位、原磁盘的分区顺序和空闲区位置。第一篇已经讲过分区过程，这里只保留最后一道核查：写盘前确认格式化清单。

我这次确认的是新建的Linux根分区使用ext4并格式化；已有EFI分区复用，Windows分区保留。电脑上的具体编号是历史现场信息，不应作为读者的操作模板。如果安装器最后一页列出了原本打算保留的分区，先返回检查，别带着疑问确认写盘。

## 六、安装完成后还是进Windows，是否要重新安装？

先移除安装U盘，再看固件启动菜单是否有Ubuntu入口和Windows Boot Manager。主动选择Ubuntu入口，是区分“系统装好了但启动顺序未选中”和“系统确实不能启动”的第一步。

如果进入桌面后不确定当前从哪里启动，可运行：

```bash
findmnt -no SOURCE,FSTYPE /
lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINTS
```

第一条显示根文件系统的来源，第二条帮助把它映射到设备。Live环境可能显示叠加文件系统；加密或逻辑卷安装可能显示映射设备，不能要求所有结果都长成同一个分区名。[Ubuntu 22.04：findmnt手册](https://manpages.ubuntu.com/manpages/jammy/man8/findmnt.8.html)

我的记录已经确认Ubuntu从SSD启动。若读者遇到的是“固件里没有入口”“出现grub提示符”或“内核加载后黑屏”，请分别记录现象。它们需要不同信息，本篇不在缺少分区和启动状态的情况下给出重装GRUB、删除EFI目录等命令。

## 七、Windows突然要求BitLocker恢复密钥，是装坏了吗？

本次确实见到了BitLocker恢复界面。启动环境或安全相关设置发生变化，可能触发恢复流程；恢复界面本身并不能证明磁盘数据丢失。

先按界面显示的密钥ID寻找对应恢复密钥，可能在本人Microsoft账户、组织账户、先前打印件或备份中。微软的恢复说明列出了这些查找渠道。不要把整张含恢复密钥的照片发到公开帖子，也不要通过反复格式化来绕过恢复。[微软：查找BitLocker恢复密钥](https://support.microsoft.com/en-us/windows/security/encryption/find-your-bitlocker-recovery-key)、[微软：BitLocker恢复概述](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/recovery-overview)

我的现有记录没有完整的“Windows重新进入后逐项检查文件”的回执，所以不能把“Ubuntu能启动”写成“双系统所有内容均已验收”。对读者而言，最终检查应包括分别启动两个系统、打开重要文件，并确认今后可以找回恢复密钥。

## 八、怎样给下一次排错留一份有效记录？

不用保存几百行没有重点的日志。记清楚电脑型号、Ubuntu版本、卡住阶段、完整错误、最近一次变更，再附必要的分区信息即可。记录“做过只读检查，没有修改”和“执行了修复，重启后通过”，比笼统写“处理过了”有用得多。

安装完成的最低验收可以分三步：不插U盘启动Ubuntu；确认系统确实来自目标硬盘；重新启动Windows并检查重要文件。完成到哪一步，就记录到哪一步。

## Linux命令小板块

| 命令 | 用途 | 本文边界 |
|---|---|---|
| `lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINTS` | 对照分区类型、卷标和挂载位置 | 只读查看，不创建分区 |
| `findmnt -no SOURCE,FSTYPE /` | 查看当前根文件系统来源 | 映射设备需要进一步对照 |
| `uname -r` | 记录当前运行的内核版本 | 不是驱动兼容性测试 |

先确定启动到了哪一步，再选择下一项检查。能解释每一步的作用，排错就不会变成不断重装。
